# G1 Multi-Teacher Distillation Method Contract

## Problem

Standing, commanded walking, and height control are partially conflicting robot
behaviors. They should not be averaged into one undifferentiated behavior target.
The method must preserve each teacher's role while producing one deployable
student policy.

## Teacher Policies

- `design_id`: `DISTILL-DP-01`
- `block_id`: `DT-M-01`
- Meaning: role-specific teacher actors provide action targets for states owned
  by their behavior role.
- Current inputs: `G1StandStill` SAC teacher and `G1WalkFlat` SAC teacher.
- Future input: a qualified height-control teacher with an explicit observation
  contract.
- Output: detached 29-D teacher actions plus teacher/checkpoint identity.
- Assumption: each teacher is valid only inside its declared role and observation
  semantics.
- Forbidden: treating `G1WalkFlat` as a height teacher, or using standing targets
  for active velocity commands.

## Command Intent

- `design_id`: `DISTILL-DP-02`
- `block_id`: `DT-M-02`
- Meaning: any non-zero planar or yaw velocity command is walking intent;
  no task command is standing intent.
- Input: command tensor `[vx, vy, vyaw]` and explicit thresholds.
- Output: `active` or `inactive` intent and the corresponding expert/teacher role.
- Ownership: command semantics belong to the task/collection contract, not to
  checkpoint filenames or an unconstrained learned router.
- Interaction: intent labels Role Data, selects expert behavior loss, selects
  DAgger rollout expert, and selects deployment expert.
- Forbidden: admitting in-place stepping samples into standing data; requiring a
  large velocity before walking becomes active; silently changing thresholds
  between collection and deployment.

## Role Data

- `design_id`: `DISTILL-DP-03`
- `block_id`: `DT-M-03`
- Meaning: every training row retains its role, command, intent, student
  observation, teacher observation, and teacher action target.
- Inputs: teacher-policy rollout data, student-policy DAgger states, and source
  metadata.
- Output: `DistillationTensorDataset` with preserved semantic labels.
- Assumption: 98-D stand/walk observations share the declared student contract.
- Forbidden: merging incompatible observation dimensions, inferring quality from
  sample count alone, or losing role/intent labels during save/load.

## MoE Student

- `design_id`: `DISTILL-DP-04`
- `block_id`: `DT-M-04`
- External execution block: `DT-X-01`.
- Meaning: one student checkpoint contains role-specialized experts and a routing
  mechanism; specialization is part of the method, not only a diagnostic.
- Input: 98-D actor observation.
- Output: one 29-D action.
- Deployment output: one student checkpoint maps current command intent to the
  corresponding expert action through the normal G1 environment contract.
- Current mapping: walking/active -> expert 0; standing/inactive -> expert 1;
  expert 2 is reserved and has no accepted active role.
- Training rule: expert-specific behavior cloning must update only selected
  experts; inactive expert optimizer state must not move parameters.
- Required behavior: zero command stands; any velocity command walks; returning
  to zero command recovers standing without falling.
- Forbidden: claiming a mixture is a standing expert; assigning expert 2 a
  semantic role without a teacher and contract version; choosing policy identity
  by file size; silently loading a different checkpoint; or using action
  non-zero/finite as a physical-quality pass.

## Student-State DAgger

- `design_id`: `DISTILL-DP-05`
- `block_id`: `DT-M-05`
- Meaning: close the behavior-cloning distribution gap by querying the teacher
  on states generated by the corresponding student expert.
- Input: role-conditioned student rollout states and teacher action labels.
- Output: aggregated role-specific student-state data and updated selected expert.
- Interaction: rollout expert, behavior-loss expert, and deployment expert must
  be the same semantic role.
- Outer-loop contract: DAgger iteration `k` must roll out the student produced
  by iteration `k-1`, query the teacher on those newly visited states, aggregate
  datasets `1..k`, update the selected expert, and then repeat with the updated
  student. Multiple minibatch optimizer steps on one fixed dataset are inner
  optimization, not additional DAgger iterations.
- Formal execution: `training.online_dagger=true` reaches the iterative owner;
  `training.dagger_iterations` counts outer rollout/update cycles, while
  `training.dagger_updates_per_iteration` counts inner optimizer updates within
  each cycle.
- Formal multi-role workflow semantics, role artifact reuse, resume, and fork
  are owned by `DISTILL-TRAIN-v001`. The low-level single-role route remains a
  diagnostic primitive and is not the default human workflow.
- Forbidden: collecting with a soft mixture while training/deploying a pure
  expert; replacing prior DAgger evidence instead of aggregating it; treating a
  shape-valid update as proof of physical stability; describing one manual
  `collect -> merge -> offline finetune` sequence as iterative DAgger; or using
  a large offline update count as a substitute for a new student rollout.

## Required Evidence

1. Contract tests: dimensions, labels, selected expert, inactive expert isolation,
   checkpoint roundtrip, and collection/deployment threshold agreement.
2. Integration tests: exact Hydra owner route reaches collection, training,
   checkpoint save/load, and playback.
3. Live tests: repeated reset standing, stand-to-walk transitions at multiple
   commands, walk-to-stop recovery, and long-horizon termination/tilt/base-height.
4. Identity evidence: checkpoint hash, runtime config, parent checkpoint,
   teacher sources, and exact launch command.

## Current Acceptance Status

Contract semantics are active. End-to-end policy quality is not accepted. The
current candidate checkpoints remain evidence artifacts until live reset and
transition gates are defined and passed.
